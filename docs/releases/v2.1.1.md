# Control Plane v2.1.1

Status: published on 2026-08-04 as immutable tag and GitHub Release `v2.1.1`
at commit `934a42c295496583baf754738e34a3bbe6855a0c`.

## Alignment

- selects product version `2.1.1` consistently in runtime, lock, adoption and
  deterministic release assets;
- supports an explicit `2.1.0` to `2.1.1` project-local upgrade while
  preserving the original exact rollback;
- includes the versioned `install-control-plane` skill fixed to the approved
  `v2.1.1` release;
- records bounded API-observed commit, tree, run attempt and successful gates
  in official candidates while rejecting local self-attestation and keeping
  ordinary local candidates pending by default.

## Authority

The four retained release assets remain non-authorizing: `authorizes=false` and
`release_authorized=false`. A successful workflow does not create a tag,
GitHub Release, installation, commit, merge or deployment. Each transition
requires its own explicit authority and independent provider observation.

## Compatibility

The supported `adopt` and `upgrade` commands are unchanged. Projects installed
from v2.1.0 use `upgrade plan`, inspect the immutable plan, then `upgrade apply`
and `adopt verify`. The original adoption rollback remains available and is
exercised before the release is considered ready.
